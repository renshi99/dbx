# XXL-JOB 管理连接

DBX 桌面版与 Web 版通过共用 Rust HTTP 客户端接入 XXL-JOB 原生调度中心。兼容模式为 2.4.x / 2.5.x，协议测试基线为官方 2.4.0 和 2.5.0。

## 建立连接

在连接选择器选择 XXL-JOB，填写完整地址，例如 `https://scheduler.example.com/xxl-job-admin`。反向代理前缀会保留，地址不得包含账号、查询参数或片段。选择实际版本：2.5.x 会对执行日志做 HTML 转义，DBX 根据选择的版本解码一次并按纯文本显示。

使用原生用户名和密码登录，不填写执行器通信 access token。密码复用 DBX 凭据保存机制；关闭保存密码后只保留当前会话凭据。登录 Cookie 仅位于 Rust 客户端内存中，不传给浏览器或持久化到连接配置。支持现有连接传输层，TLS 默认验证证书；HTTPS 隧道应填写证书对应的主机名。

管理员选择“自动发现”，可分页查看执行器的 AppName、名称和注册地址。普通账号选择“手动范围”，每行填写一个执行器 ID 和可选名称，例如：

```text
1 默认执行器
5 报表任务
```

普通账号的手动配置不是授权：测试连接和后续操作使用调度中心带权限检查的日志查询验证该账号的执行器权限。任务写操作另外核对任务的实际执行器归属；日志正文只能读取之前在同一连接、执行器的日志列表中返回过的记录。范围最多 100 个执行器。权限错误会明确显示，不会作为空列表处理。

## 首版功能

- 任务按执行器、描述、Handler、负责人和调度状态查询，每页 20 条。
- 新增 BEAN 任务；编辑常规任务参数，保留运行模式和 GLUE 源码。新增任务保持停止状态，启动调度是独立操作。
- 删除任务、启动或停止调度、手动执行一次。停止调度不会终止已经运行的实例。
- 手动执行默认带入已保存参数，可覆盖本次参数和执行器地址，不修改任务配置。成功响应仅表示已提交调度，执行结果以日志为准。
- 按任务 ID、状态和调度中心时区的时间范围查询调度日志。执行日志按行号每 2 秒读取；隐藏页面暂停、关闭取消在途请求，结束后停止。界面保留最近 5 MiB 正文。
- 保存当前标签页的视图、执行器、筛选条件和页码，切换执行器时重置任务、日志页码。

写操作经过 DBX 只读锁和已有生产环境保护。写请求不会自动重试；超时、断流或服务端异常后显示结果不确定，应刷新任务/日志确认，再决定是否重提。查询操作在明确的会话失效时允许重新登录并重试一次。日志读取失败后暂停，需手动继续。

不包含 GLUE 源码编辑、执行器增删改、用户管理、运行报表、终止运行实例、清理日志、SSO 和 MCP 接入。定制发行版可能需要额外适配；没有可靠的服务版本探测接口，兼容版本由用户选择，不将其报告为探测到的版本。

## 实现与测试

连接类型描述符是注册源；修改后执行 `pnpm generate:connection-types`。客户端存放在现有连接池中，复用凭据、配置变更失效、连接断开及传输层生命周期。

前端导出类型化 `xxljob*` 操作，桌面调用 `xxljob_request`，Web 调用 `POST /api/xxljob/request`，载荷为 `{ operation, request }`。核心业务维护操作白名单，固定路径访问调度中心；所有管理请求与凭据都经 Rust 后端处理。

```sh
pnpm check:connection-types
pnpm exec vue-tsc --noEmit --project apps/desktop/tsconfig.json
pnpm exec vitest run apps/desktop/src/lib/xxljob/xxljob.spec.ts apps/desktop/src/components/xxljob
cargo test -p dbx-core --no-default-features --features sqlite-bundled xxljob --lib
cargo check -p dbx-web -p dbx
```

自动化测试使用本地模拟 HTTP 服务，不操作真实调度任务。真实环境联调需在 2.4.0、2.5.0 的独立测试执行器中分别使用管理员、受限账号验证连接、任务增删改、启停、触发、日志、权限拒绝和隧道。执行日志由调度中心转向执行器读取，因此还要求调度中心能访问执行器。当前没有提供可用的真实 XXL-JOB 环境，真实联调尚未完成。
